# Transcriber Live AI Workspace Redesign

## Objective

録音とリアルタイム文字起こしを主役に保ったまま、録音中の任意時点で途中要約と質問を実行できるようにする。同時に、5画面の見た目と状態表現を統一し、起動・通信・空データを誤認しない静かな業務用UIへ更新する。

## Scope

- 録音中AIパネル: 途中要約、質問、対象時間の選択、回答履歴
- 共通デザイン基盤: 色、余白、ボタン、フォーム、通知、ローディング、空状態
- 文字起こし、話者、辞書、履歴、設定の5画面
- ライブAI用バックエンドAPIとClaude優先/Geminiフォールバック
- 自動テスト、主要画面のスクリーンショット、実録音の通し確認

対象外:

- 発言単位の手動選択
- 回答からカレンダー、Slack、メールを直接実行する機能
- AI回答の永続保存と終了後議事録への自動統合
- 新しいUIライブラリの追加

## Experience Principles

1. 文字起こしを常に最大の作業面として扱う。
2. シアンは選択・フォーカス、赤は録音・削除、黄は警告に限定する。
3. 通信待ちを空データとして見せない。
4. 頻繁な操作にアニメーションを付けず、AIパネル開閉だけ160msで補助する。
5. 録音とAIを障害境界で分離し、AI失敗で録音を止めない。

## Application Shell

上部ナビゲーションは維持する。各画面は共通のページヘッダー、ツールバー、通知バナー、スクロール領域を使う。4px/8pxの余白単位、最大8pxの角丸、1pxの境界線を基本とし、カードの入れ子は作らない。

ボタンは `primary`、`secondary`、`danger`、`icon` の4種に整理する。重要操作にはアイコンとラベルを併記し、アイコンだけの操作にはツールチップと `aria-label` を付ける。フォーカスリングを常に表示可能にし、`prefers-reduced-motion` では変形を無効化する。

## Recording And Live AI

録音デバイス、セッション名、録音操作を上部のコンパクトな操作バーへまとめる。文字起こし一覧は残り領域を使用する。AIボタンを押すと右側に幅360px前後のパネルを開き、文字起こし領域を押し潰し過ぎない範囲でリサイズする。狭い画面ではオーバーレイ表示に切り替える。

AIパネルには共通の対象範囲セレクターを置く。

- 会議全体
- 過去5分
- 過去15分
- 過去30分
- 過去60分
- 任意の過去N分

タブは `途中要約` と `質問`。要約は実行ボタン、質問は複数行入力と送信ボタンを持つ。結果には対象時間、生成時刻、利用エンジンを表示する。実行時点の文字起こしをスナップショットとして扱い、その後の発言で既存回答を書き換えない。回答履歴は録音セッション中、タブ移動後もフロント状態として保持する。

## Other Screens

### Speakers

話者一覧と編集領域を左右分割し、名前変更、サンプル確認、統合を一画面で完結させる。サンプル不足や埋め込み未生成を状態ラベルで示す。

### Dictionary

検索、追加、置換ルールを表形式で整理する。保存中、保存済み、重複、入力不備を行の近くに表示する。既存のフィラー設定も同じ画面内の独立セクションに置く。

### History

一覧は既存の情報密度を維持する。チェック、お気に入り、行遷移のクリック領域を分離する。詳細画面は発言とスクリーンショットを時間対応で同期し、TXT/JSON/MDの出力操作を共通ツールバーへ置く。MDはAI向けMarkdown出力を指す。

### Settings

接続、音声認識、AI、録音、保存のセクションへ再編する。接続テスト、モデル状態、保存結果、エラーを該当設定の近くに表示する。

## Backend API

`POST /api/summary/live` を追加する。リクエストは以下を受け取る。

```json
{
  "client_id": "optional-client-id",
  "mode": "summary",
  "range_minutes": 15,
  "question": null
}
```

`range_minutes` が `null` の場合は会議全体。`mode` は `summary` または `question`。質問モードでは空質問を400で拒否する。バックエンドはクライアントに対応する実行中セッションから発言をコピーし、最新の `timestamp_end` を基準に範囲を切り出す。切り出し後に空なら400を返す。

レスポンス:

```json
{
  "content": "Markdown text",
  "mode": "summary",
  "range_minutes": 15,
  "range_start_seconds": 420.0,
  "range_end_seconds": 1320.0,
  "generated_at": "ISO-8601",
  "entry_count": 42,
  "usage": {
    "model": "claude-code",
    "billing": "claude-subscription"
  }
}
```

既存の要約エンジン選択と課金境界を再利用する。ただしライブ用プロンプトは終了後要約と分離する。Claude Codeを優先し、サブスク上限に該当するエラーの場合だけGeminiへフォールバックする。CLI不在、認証不備、通常の実行エラーでは勝手にGeminiを消費せず、そのエラーを返す。

同一ライブセッションのAI処理は1件に制限し、処理中の重複要求は409を返す。AI処理はセッションの録音タスクやロックを保持しない。

## Frontend State

AIパネルの開閉、選択範囲、タブ、質問入力、回答履歴、処理中状態、エラーを `Transcription` 配下で管理する。`Transcription` 自体は常時マウントされるため、トップタブを移動しても録音中履歴を保持できる。録音を新規開始した時点で前セッションのAI履歴をクリアする。

## Loading And Error States

- バックエンド起動中: 専用ローディング。空状態を表示しない。
- 履歴初回ロード中: 一覧スケルトン。成功後にだけ空状態を表示する。
- AI処理中: 該当ボタンを無効化し、録音操作は有効のままにする。
- AI失敗: 入力と既存回答を残し、再試行を提示する。
- WebSocket切断: 現在の再接続表示とREST同期を維持する。

## Testing

バックエンド単体テスト:

- 全体、5/15/30/60/任意分の範囲切り出し
- 境界時刻をまたぐ発言の扱い
- 空セッション、空質問、不正範囲
- クライアント別セッション
- 同時要求の409
- Claude優先、許可されたGeminiフォールバック
- AI失敗中もセッション状態がrunningのまま

フロントE2E:

- AIパネルの開閉、タブ、範囲、任意分入力
- 要約と質問のリクエスト内容
- 処理中の多重送信防止、失敗後の入力保持、再試行
- タブ移動後の回答履歴保持、新規録音時のリセット
- 各画面の読込中、空、エラー状態
- 履歴のチェック、お気に入り、行遷移の当たり判定
- 履歴詳細の発言・スクリーンショット同期

最終確認ではTypeScript、Pythonテスト、Playwrightに加え、デスクトップと狭幅のスクリーンショットを確認し、可能なら実音声で録音からライブ要約まで通す。
